# 总结 B站 视频

**前置条件**：先看视频（`watching.md`）。总结是最后一步。

## 模式

三种模式，模型根据用户意图选择：

| 模式 | 用户说 | 行为 |
|---|---|---|
| **闲聊**（默认） | "看看"、"聊聊"、不指定 | 对话体，挑有趣的聊，引导讨论 |
| **速览** | "总结一下"、"讲了什么"、"大概" | 要点列表，简明扼要 |
| **深度** | "整理一下"、"写文章"、"出导图" | 结构化输出 |

### 闲聊（默认）

用户没指定模式时默认闲聊。从视频里挑有意思的角度聊，问用户怎么看。轻松对话感。

应包含：
- **标题 + UP主**：谁、什么
- **2-3 个有意思的点**：带个人语气的发现
- **一个讨论钩子**：问用户的看法
- **关键帧**：有视觉亮点就放几张

### 速览

要点列表，一眼看完。

应包含：
- **标题 + UP主 + 时长**
- **核心内容**：3-5 个要点，每点一行
- **值得看吗**：一句话评价
- **关键词**
- **关键帧**：有代表性就放一张

### 深度

两种形式，根据用户措辞选：
- **文章**："写篇文章"、"整理成文档"
- **思维导图**："画导图"、"mind map"、"梳理结构"

**文章**应包含：
- 标题 + UP主 + 链接
- 按内容自然分段，每节有小标题和时间范围
- 在需要画面佐证的地方嵌入关键帧
- 总结段落

**思维导图**应包含：
- 中心主题（一句话）
- 层级结构由内容决定，不预设数量和深度
- 每个节点带时间戳 [MM:SS]
- 在需要画面的节点下嵌入关键帧
- 总结

**输出**：使用 markmap 生成交互式思维导图文件。

markmap 输入格式：标准 markdown——`#` 中心节点，`##` 一级分支，`###` 二级，`-` 叶节点。图片用 `![](path)`：

```markdown
---
title: <视频标题>
markmap:
  initialExpandLevel: 2
---

# <中心主题>
## <分支1> [MM:SS]
- 要点
- ![](frame.jpg)
## <分支2> [MM:SS]
- 要点
```

执行命令：
```bash
# 1. 按上面格式写结构化 .md 文件
# 2. 把引用的帧文件拷到同一目录
# 3. 渲染成交互式 HTML
markmap /tmp/bilibili-mindmap.md --offline -o ~/bilibili-<bv_id>-mindmap.html
# 4. 转 PNG
python3 scripts/html_to_png.py ~/bilibili-<bv_id>-mindmap.html
```

生成前加载 markmap skill 了解具体用法。输出为自包含 HTML 文件，浏览器打开可交互缩放拖拽，markdown 中相对路径引用的帧图片会内联渲染。

## 关键词

任何模式都要附 3-5 个关键词。从视频核心主题提取。格式：`关键词：A、B、C`

## 默认行为

- 未指定模式 → 闲聊
- 始终含关键词
- 提及特定时刻时始终带时间戳

## 多P / 合集

watching.md 阶段零可能返回 `multi_p` 或 `collection` 类型。默认只处理第一个 P / 第一个视频。

- 总结默认只覆盖当前处理的那一个 P / 视频
- 提醒用户还有 N 个分P / 视频未处理，列出标题（来自 index.yaml）
- 用户要求处理全部时：watching.md 拆子代理逐个分析 → 总结阶段合并各子代理的结果
  - 闲聊：挑跨分P / 跨视频的有趣对比来聊
  - 速览：每个 P / 视频一组要点
  - 深度文章：按视频/分P 分节，加总述段落
  - 思维导图：每个 P / 视频一个一级分支
